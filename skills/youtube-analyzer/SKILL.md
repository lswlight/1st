# 유튜브 영상 분석 → 내 영상 제작 활용

목표는 "요약"이 아니라 **내 영상에 옮겨 쓸 수 있는 설계도**를 뽑는 것이다.
모든 결과는 한국어로 작성한다.

## 0. 입력 확인

- 유튜브 URL 1개 이상. 없으면 링크를 달라고 한다.
- 선택 정보(없으면 묻지 말고 기본값으로 진행): 내 채널 주제/타깃, 만들 영상 형식(쇼츠 vs 롱폼), 분석 깊이.
- 여러 URL이면 각각 분석 후 마지막에 **공통 패턴 비교표**를 추가한다.

## 1. 영상 데이터 수집 — 무료 경로가 기본

아래 순서대로 시도한다. **유료 경로(D)는 사용자가 명시적으로 허락할 때만** 쓴다.

### A. Gemini API로 영상 직접 분석 (기본, 무료 한도 내)
Gemini는 유튜브 URL을 받아 영상의 화면과 소리를 직접 보고 듣는다. 이 스킬의 `scripts/gemini_analyze.py` 를 코드 실행 도구로 돌린다.

```bash
python3 <이 스킬 폴더>/scripts/gemini_analyze.py "<유튜브 URL>" --out /tmp/gemini_raw.md
```
- 키는 `GEMINI_API_KEY` 환경변수나 `config/gemini_api_key.txt` 에서 읽는다. 둘 다 없으면 사용자에게 Google AI Studio(aistudio.google.com)에서 무료 키를 받아 달라고 안내하고 B로 넘어간다. **키를 화면에 다시 출력하지 않는다.**
- 10분이 넘는 영상은 `--low-res` 를 붙이고, 필요하면 `--start 0s --end 300s` 처럼 나눠 분석한 뒤 합친다.
- 결과 파일에는 첫 15초 정밀 기록, 장면 표, 편집 스타일, 대본 전문, 구성 구간이 들어 있다. 이것을 2단계 리포트의 원재료로 쓴다.
- 네트워크 오류(접속 차단, 403 proxy 등)나 무료 한도 초과(429)가 나면 원인을 한 줄로 알리고 B로 넘어간다.
- 공개(또는 일부 공개) 영상만 분석된다. 비공개 영상은 C로 처리한다.

### B. Gemini 앱 결과 붙여넣기 (무료, 코드 실행이 안 될 때)
사용자에게 안내한다:
> Gemini 앱에 영상 링크와 아래 문장을 넣고, 나온 결과를 그대로 붙여넣어 주세요.
> "이 영상을 장면별로 시간, 화면, 카메라, 대사 원문, 화면 자막, 편집 효과, BGM/효과음까지 표로 정리하고, 첫 15초는 1초 단위로, 대본 전문도 시간과 함께 적어줘."

### C. 대본(자막) 직접 붙여넣기 (무료, 최소 정보)
> 유튜브 앱/웹에서 설명란 → "스크립트 표시"를 눌러 전체 복사 후 붙여넣어 주세요. 썸네일 캡처를 함께 주시면 썸네일도 분석합니다.

화면 정보가 없으므로 장면·편집 항목은 "(대본 기반 추정)"으로 표시한다.

### D. Higgsfield 장면 분석 (유료, 허락받은 경우만)
사용자가 "Higgsfield로 분석해줘"처럼 명시적으로 요청했을 때만 쓴다. 쓰기 전에 크레딧이 들 수 있다고 알리고, 가능하면 `balance` 로 잔액을 먼저 보여준다.
1. `video_analysis_create` 에 `youtube_url` 을 넣는다. 처리에 3~5분 걸리고 영상이 길수록 정확도가 떨어진다고 알린다.
2. `video_analysis_status` 가 `completed` 가 될 때까지 확인한다.

### 메타데이터 보강 (A~D 공통)
WebFetch/WebSearch 같은 웹 도구가 있으면 제목, 채널, 조회수, 업로드일, 설명란, 인기 댓글을 가능한 만큼 수집한다. 실패해도 넘어간다.

어느 경로로 얻은 정보인지 리포트 머리에 표시한다. **보지 못한 내용은 지어내지 않는다.** 추정이면 "(추정)"을 붙인다.

## 2. 분석 리포트 작성

`references/report-template.md` 의 구조를 그대로 따른다. 핵심 관점:

1. **한 줄 요약 & 성공 요인 가설** — 이 영상이 먹힌 이유 3가지
2. **훅(첫 3초/15초)** — 무엇을 보여주고 어떤 질문/긴장을 만들었나, 훅 유형 분류
3. **구성(타임라인)** — 구간별 역할(훅→문제제기→전개→반전→결론→CTA)과 길이 비율
4. **장면 분석 표** — 시간 | 화면 | 대사/자막 | 편집기법 | 목적
5. **편집 리듬** — 평균 컷 길이 추정, 자막 스타일, B롤/효과음/BGM 사용, 화면 전환
6. **제목·썸네일·설명란** — 키워드, 호기심 장치, 숫자/대비 사용
7. **대본 패턴** — 문장 길이, 말투, 반복 구조, 재사용 가능한 문장 템플릿
8. **시청자 반응** — 댓글에서 드러난 니즈/불만 (데이터 있을 때만)
9. **훔칠 것 / 버릴 것** — 내 채널에 적용할 요소 vs 피할 요소

## 3. 내 영상 적용안 (사용자가 원하거나 제작 의도가 보이면 기본 포함)

`references/production-handoff.md` 를 따라 작성한다:
- 내 주제로 바꾼 **제목 후보 5개 + 썸네일 문구 3개**
- **대본 초안** (분석한 구조를 그대로 차용, 구간별 시간 표기)
- **스토리보드 표** (컷 번호 | 길이 | 화면 | 대사 | 생성 방식)
- 각 컷의 **Higgsfield 이미지/영상 생성 프롬프트** (영문 프롬프트 + 한국어 설명)

생성은 크레딧을 쓰므로 **프롬프트까지만 만들고, 실제 생성은 사용자가 요청할 때만** 실행한다.

## 4. 내 영상 검증 (선택)

**무료 방법:** 완성본을 유튜브에 일부 공개로 올리고 A 경로로 같은 분석을 돌려 레퍼런스와 나란히 비교한다.

**유료 방법(허락받은 경우만):** 사용자가 자기 완성본을 주면 Higgsfield `media_upload_widget`(로컬 파일) 또는 `media_import_url`(웹 URL)로 올린 뒤 `virality_predictor`(action: create, model: virality_predictor)로 훅 강도·이탈 위험을 확인하고, 1단계 레퍼런스 분석과 비교해 개선점을 제시한다.

## 5. 결과 보관

- 기본: 대화 안에 리포트로 출력.
- 사용자가 원하면 Notion/Google Drive 커넥터로 "유튜브 분석 아카이브" 페이지에 저장한다 (영상 제목, URL, 분석일, 훅 유형, 핵심 인사이트를 속성으로).
