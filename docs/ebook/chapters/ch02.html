무엇을 했나한 문단으로 시작한 앱

모든 것은 아래 한 문단에서 시작했습니다. 맞춤법도 다듬지 않고, 휴대폰으로 생각나는 대로 쳐서 보낸 첫 요청입니다.

실제 첫 요청 (원문 그대로)
나
나는 수입 지출 앱을 만들고 싶어. 다른 복잡한 기능은 빼고 나의 수입(월급)을 입력하고 내가 사용하는 카드실적 카카오톡 or 문자 or 카드지출 앱의 알림이 날라오면 이를 캐치하고 자동으로 바로 기입을 하는 형태의 어플을 만들고 싶어.
AI
안드로이드의 '알림 접근' 기능으로 문자·카카오톡·카드사 앱 알림을 읽어서, 금액·가맹점·카드사를 뽑아 폰 안에 저장하는 앱으로 만들겠습니다. 외부 라이브러리 없이 안드로이드 기본 기능만 쓰고, 설치 파일은 GitHub Actions에서 자동으로 만들어 폰에서 바로 받을 수 있게 하겠습니다.

이 요청에는 좋은 요청의 요소가 다 들어 있습니다.

  • 뺄 것: "다른 복잡한 기능은 빼고" → 예산, 카테고리, 클라우드 같은 기능을 처음부터 넣지 않게 됩니다.
  • 사람이 할 일: "수입(월급)을 입력하고" → 월급은 직접 입력.
  • 자동으로 될 일: "알림이 날라오면 캐치하고 바로 기입" → 앱의 핵심 기능.
  • 재료: "카카오톡 or 문자 or 카드지출 앱" → 어떤 알림을 읽을지.

기술적인 단어는 하나도 없습니다. 그래도 충분합니다. "무엇이 들어오면, 무엇이 자동으로 되면 좋겠다"는 형태로 말하면 AI가 방법을 골라 줍니다.

왜AI가 고른 구조, 쉬운 말로 풀기

AI가 제안한 구조를 이해할 필요는 없지만, 대강 알아 두면 나중에 대화가 훨씬 쉬워집니다. 이 앱은 네 부분으로 되어 있습니다.

알아 두면 좋은 질문 하나 AI가 낯선 단어를 쓰면 "그게 뭐야? 쉽게 설명해 줘"라고 물어보세요. 저자도 처음에는 APK, AAB, 커밋 같은 말을 몰랐습니다. 이 책 끝의 용어집에도 정리해 두었습니다.

왜내 PC에 아무것도 깔지 않은 이유

보통 안드로이드 앱을 만들려면 PC에 '안드로이드 스튜디오'라는 큰 개발 프로그램을 깔고, 앱을 '빌드'(코드를 설치 파일로 바꾸는 작업)해야 합니다. 설치만 몇 기가바이트이고 설정도 까다롭습니다. 저자는 이 과정을 통째로 건너뛰었습니다.

  • 코드 작성은 Claude Code 클라우드 세션(인터넷 저편의 작업용 컴퓨터)에서 AI가 합니다.
  • 빌드는 GitHub Actions(GitHub이 무료로 빌려주는 컴퓨터)가 코드가 바뀔 때마다 자동으로 합니다.
  • 설치 파일 배포는 GitHub Releases(저장소에 딸린 다운로드 게시판)의 고정 링크에 자동으로 올라갑니다.

링크가 바뀌지 않으니, 가족에게 한 번 알려 주면 업데이트할 때도 같은 링크를 누르면 됩니다.

따라 하기첫 앱을 만드는 순서

  1. Claude Code 세션 열기claude.ai/code(또는 Claude 앱의 Code 탭)에서 1장에서 만든 저장소를 고르고 새 세션을 엽니다.
  2. 만들 앱을 한 문단으로 설명하기위의 첫 요청처럼 "무엇을 입력하고, 무엇이 자동으로 되면 좋겠다"를 씁니다. 꼭 넣을 것과 뺄 것을 함께 말하세요.
  3. 설치 방식도 함께 요청하기"내 PC에는 아무것도 안 깔고 싶어. 폰에서 링크로 바로 받아 설치할 수 있게 해 줘"라고 덧붙입니다. 그러면 AI가 GitHub Actions 자동 빌드와 Releases 링크를 같이 만들어 줍니다.
  4. AI의 질문에 답하기AI가 "카드사는 어디를 쓰세요?", "알림 문구 예시가 있나요?"처럼 되물을 수 있습니다. 실제 카드 문자 몇 개를 붙여 넣어 주면(카드번호·이름은 가리고) 첫 버전부터 정확도가 높아집니다.
  5. 작업이 끝나면 '푸시'되었는지 확인AI가 코드를 저장소에 올리는 것을 '커밋·푸시'라고 합니다. AI가 "푸시했습니다"라고 하면 GitHub 저장소의 Actions 탭에서 빌드가 돌고 있는지 볼 수 있습니다. 노란 점은 진행 중, 초록 체크는 성공, 빨간 X는 실패입니다.
  6. 빌드가 실패하면 그대로 말하기빨간 X가 보이면 "빌드가 실패했어, 확인해 줘"라고만 하면 됩니다. 클라우드 세션의 AI는 실패 기록을 직접 읽고 고칩니다.
  7. 다운로드 링크 받기초록 체크가 뜨면 AI에게 "폰에서 받을 링크 알려 줘"라고 합니다. 이 링크를 폰 브라우저로 열면 설치 파일(APK)이 내려받아집니다. 설치는 3장에서 이어집니다.
APK가 뭔가요? APK는 안드로이드 앱 설치 파일입니다. PC의 setup.exe와 비슷합니다. 플레이스토어를 거치지 않고 이 파일로 직접 설치하는 것을 '사이드로딩'이라고 부릅니다. 나중에 플레이스토어에 올릴 때는 AAB라는 다른 형식(스토어 업로드용 앱 파일)을 씁니다(9장).

업데이트해도 기록이 지워지지 않게: 같은 서명 키

안드로이드 앱 설치 파일에는 '이 앱을 누가 만들었는지'를 증명하는 서명이 들어 있습니다. 새 버전의 서명이 예전 버전과 다르면 폰은 업데이트를 거부하고, 앱을 지웠다 다시 깔아야 합니다. 그러면 가계부 기록이 모두 사라집니다.

그래서 이 앱은 매번 같은 서명 키(저장소에 보관한 연습용 키)로 빌드되도록 설정했습니다. 저자가 이것을 미리 알고 요청한 것은 아니고, 설치하다가 '앱이 설치되지 않았습니다'를 겪으며 서명·빌드 설정을 바로잡았습니다(3장). 처음부터 이렇게 말해 두면 같은 일을 겪지 않습니다.

미리 말해 두면 좋은 문장
나
업데이트할 때 앱을 지우지 않고 덮어 설치할 수 있게, 항상 같은 서명으로 빌드해 줘. 기록이 지워지면 안 돼.
여기서 쓴 서명 키는 '연습용'입니다 가족끼리 직접 설치해 쓰는 앱은 연습용(디버그) 키를 저장소에 두고 써도 큰 문제가 없습니다. 하지만 플레이스토어에 올릴 앱의 서명 키(업로드 키)는 절대 저장소에 두면 안 됩니다. 9장에서 따로 만들어 GitHub Secrets에 숨겨 둡니다.

막혔던 점첫 빌드에서 만난 것들

AI가 만든 첫 버전이 실제 카드 문자를 못 읽는다

당연한 일입니다. 카드사마다, 문자·카카오톡·앱마다 문구가 다릅니다. 첫 버전은 '대략 이런 모양'을 기준으로 만들어지므로, 실제 알림을 받아 보고 고치는 과정이 반드시 필요합니다. 이 반복이 4장의 내용입니다. 실망하지 말고 다음 단계로 넘어가세요.

AI 답이 너무 길고 전문 용어투성이다

"코딩 모르는 사람한테 설명하듯 짧게 말해 줘", "내가 해야 할 일만 알려 줘"라고 하면 됩니다. 한 번 말해 두면 그 세션에서는 계속 그렇게 답합니다. 영어로 답하면 "한국어로"라고 하세요.

2장 체크리스트
  • 만들 앱을 "뺄 것 / 직접 할 것 / 자동으로 될 것"으로 나눠 한 문단으로 썼다
  • "PC에 아무것도 안 깔고 폰에서 링크로 설치"를 요청했다
  • "항상 같은 서명으로 빌드해 줘(기록 유지)"를 요청했다
  • GitHub 저장소의 Actions 탭에서 빌드 성공(초록 체크)을 확인했다
  • 폰에서 열 고정 다운로드 링크를 받았다
