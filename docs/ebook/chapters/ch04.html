앱을 설치한 다음 날부터 진짜 개발이 시작되었습니다. 카드를 쓸 때마다 앱을 열어 제대로 적혔는지 확인하고, 이상하면 캡처해서 AI에게 보냈습니다. AI가 고치면 10분쯤 뒤 같은 링크로 새 버전을 받아 덮어 설치했습니다. 2주 동안 이 고리를 수십 번 돌았습니다.

이 장의 사례들은 모두 실제로 겪은 것입니다. 카드사와 알림 앱의 종류가 많아서, 처음부터 모든 경우를 맞게 만드는 것은 불가능합니다. 대신 틀린 것을 하나씩 발견해서 알려 주는 것이 사람의 일입니다. 이것이 바이브 코딩에서 가장 중요한 역할이기도 합니다. 여러분이 사용자이자 검사관입니다.

왜"안 돼" 대신 캡처를 보내는 이유

AI는 내 폰을 볼 수 없습니다. "카카오톡 알림이 안 돼"라고만 하면 AI는 추측으로 고칠 수밖에 없고, 추측은 자주 빗나갑니다. 반면 실제 알림 문구가 있으면 AI는 정확히 어느 글자 규칙이 실패했는지 알 수 있습니다. 좋은 보고에는 세 가지가 들어갑니다.

무엇예
어떤 일이 있었나"하나카드 해외 결제가 방금 있었는데"
기대와 실제"반영이 되지 않았어" / "지출로 들어갔는데 수입이어야 해"
증거알림 원문 캡처, 앱의 '최근 감지 알림' 캡처
캡처 속 개인정보 카드 알림에는 이름 일부, 카드번호 뒷자리, 잔액 등이 들어 있습니다. AI 작업에는 금액·가맹점·문구 형식만 있으면 되니, 민감한 부분은 지우거나 가리고 보내도 됩니다. 특히 이 내용이 저장소의 테스트 코드로 들어갈 때는 "이름·카드번호는 가짜로 바꿔서 넣어 줘"라고 말하세요.

따라 하기원격 진단 화면부터 만들기

몇 번 고치다 보니 같은 문제가 생겼습니다. 기록이 안 됐을 때, 앱이 알림을 아예 못 받은 것인지, 받았는데 못 읽은 것인지 알 수가 없었습니다. 그래서 AI에게 앱 안에 진단 화면을 만들어 달라고 했습니다. 이것이 '최근 감지 알림' 화면입니다.

  • 앱이 받은 문자·카카오톡·카드 앱 알림의 원문과
  • 처리 결과: 기록됨 / 결제 문구 아님 / 중복이라 건너뜀 등을 보여 줍니다.
  • 나중에 규칙을 고친 뒤 [놓친 결제 다시 읽기]를 누르면 예전에 못 읽은 알림(최근 50건)을 새 규칙으로 다시 읽어 기록합니다.

이 화면 하나로 원격 수리가 훨씬 쉬워졌습니다. 기록이 이상하면 이 화면을 캡처해서 보내면 끝입니다. 아래는 실제로 보낸 캡처입니다.

요청 예시 · 진단 기능 만들기
나
기록이 안 될 때 앱이 알림을 받았는지 못 읽었는지 내가 볼 수 있으면 좋겠어. 받은 알림 원문이랑 처리 결과를 보여 주는 화면 만들어 줘. 그걸 캡처해서 너한테 보낼게.
모든 앱에 통하는 원칙 여러분이 만드는 앱이 가계부가 아니어도, "앱이 무엇을 받았고 어떻게 판단했는지"를 사용자가 볼 수 있는 화면을 하나 만들어 두세요. 코드를 볼 수 없는 바이브 코더에게는 이것이 눈이 되어 줍니다.

사례 모음실제로 고친 12가지

각 사례는 증상 → 내가 한 말 → 원인 → 수정 순서입니다. 여러분의 앱에서 비슷한 일이 생기면 "내가 한 말"을 참고해 요청해 보세요.

01카카오톡 알림톡이 안 잡힘
증상
같은 카드사인데 문자로 온 결제는 기록되고, 카카오톡 알림톡으로 온 결제는 기록이 안 됨.
내가 한 말
"문자로 오는 것은 정상적으로 잘 되고 카카오톡으로 오는 것은 안 돼."
원인
앱이 읽는 알림 대상에 카카오톡이 빠져 있었음.
수정
카카오톡 알림도 읽되, 카드사 알림톡일 때만 기록(친구 대화는 무시). 확인하려고 같은 문구를 다시 보내 보니 기록되지 않았는데, 이것은 같은 결제를 두 번 적지 않게 하는 '중복 거르기'가 정상 동작한 것이었음.
02해외(엔화) 결제 미기록
증상
일본 사이트에서 하나카드로 엔화 결제를 했는데 기록 안 됨.
내가 한 말
"하나카드의 해외카드 결제가 방금 이루어졌는데 반영이 되지 않았어" → "환율을 연동할 수 있는 방법이 있어?" → "수수료는 여유있게 2%로 하자"
원인
원화 금액만 찾도록 되어 있어 JPY 2,280 같은 외화 금액을 못 읽음.
수정
외화 금액 인식 + 무료 환율 서비스에서 하루 한 번 환율 받기 + 해외 이용 수수료(기본 2%) 더하기. 사용처 옆에 (JPY 2,280 × 9.30원 + 수수료, 추정)처럼 계산 근거를 남김.
03클라우드 테스트는 통과, 폰에서만 실패
증상
해외 결제 규칙을 고친 뒤에도 폰에서는 처리 실패.
원인
글자 규칙(정규식) 안의 } 문자를 안드로이드 기기만 다르게 해석함. 클라우드의 테스트에서는 통과했기 때문에 발견이 늦었음.
수정
규칙을 고치고, 실제 안드로이드 환경(에뮬레이터)에서 도는 테스트를 추가해 같은 실수가 다시 나오지 않게 함.
04카드 혜택(캐시백)이 지출로 기록
증상
커피 할인 캐시백 알림(-1,500원 커피전문점 할인)이 지출로 들어감.
내가 한 말
"카드 혜택에서 … 할인받은 금액은 -(음수)로 알람이 오니 +수입 처리가 되어야 하는데 지출 처리가 되었어."
수정
금액 앞에 -가 붙은 혜택 알림은 수입으로, 내용 앞에 '카드 혜택:'을 붙여 기록. 잘못 분류된 내역은 눌러서 '수입으로 바꾸기/지출로 바꾸기'로 고칠 수 있게 함.
05새마을금고 체크카드 출금 미기록
증상
MG새마을금고 체크카드로 결제했는데 기록 안 됨.
원인
은행 앱의 알림은 읽는 대상이 아니었음.
수정
앱 이름에 은행·뱅크·금고·신협 등이 들어간 은행 앱의 알림도 읽도록 추가. (이것이 다음 사례의 고민으로 이어짐)
06체크카드 결제와 계좌이체 구분
증상
은행 앱 출금 알림을 읽자, 체크카드 결제뿐 아니라 내 계좌끼리 옮긴 돈·송금까지 지출로 들어감.
내가 한 말
"체크카드의 경우 사용시 입출금 형태로 되는데 일반 계좌 이체랑 구분할 수 있나?" → "승인 알림이 있어. 이걸 기준으로 체크카드 사용을 구분할 수 있지 않을까?"
수정
사용자의 아이디어를 그대로 규칙으로: '승인·결제·카드' 단어가 있는 알림만 결제로 기록, 승인 없는 계좌 출금은 제외(자동이체만 예외). 혹시 출금이 기록돼도 같은 금액의 입금이 5분 안에 오면 내 계좌 간 이체로 보고 삭제. 이 사례는 5장에서 자세히 다룹니다.
07KB국민카드 가맹점이 '시각'으로 기록
증상
RCS(사진·버튼이 들어간 새 문자) 형식 알림에서 가맹점 이름 자리에 결제 시각이 들어감.
수정
가맹점 추출 규칙 보완. 실제 문구('미소가득주유소')를 테스트 예시로 넣어 다시 깨지지 않게 함.
08토스 '적립' 알림이 지출로 기록
증상
"4,360원 적립됐어요" 같은 포인트 적립 알림이 지출로 들어감.
수정
적립 안내, 결제 문자 속 "포인트 적립 예정"은 기록하지 않음.
09해외 달러 결제 형식이 제각각
증상
카드사마다 33.83(USD), 31.85 달러처럼 달러 표기가 달라 일부만 기록됨.
수정
여러 표기를 모두 인식하도록 규칙 확장, 각 형식을 테스트에 추가.
10네이버페이·토스 결제
증상
네이버 앱의 네이버페이 결제 알림 미기록. 토스 결제는 '토스'로 적혔는데 실제로는 연결된 체크카드에서 빠져나간 돈.
수정
네이버 앱 결제 알림 인식 추가. 토스포인트·토스머니 결제는 결제수단 '토스'로 기록하고, 뒤따라 카드사 알림이 오면 카드 이름을 실제 카드로 바꿈(중복 기록 없이).
11카드 청구 안내가 지출로 기록
증상
현대카드 "11/12 결제금액 11,380원(11/01기준) 신한은행" 문자가 지출로 기록됨(위 캡처).
원인
'결제금액'이라는 단어와 금액이 있어서 결제 알림으로 오해. 실제로는 다음 달 카드값 청구 안내.
수정
'결제금액 … (날짜기준)' 형태의 청구 안내 문구는 제외. 결제예정금액·청구서·광고·인증번호 문자도 함께 제외 목록에 있음.
12앱 업데이트 후 놓친 결제
증상
규칙을 고치기 전에 온 알림은 고친 뒤에도 여전히 빠져 있음.
수정
'최근 감지 알림'에 [놓친 결제 다시 읽기] 버튼 추가. 저장해 둔 최근 알림을 새 규칙으로 다시 읽어 빠진 것만 기록. 이제 고친 뒤 버튼 한 번이면 지난 기록도 채워짐.

막혔던 점반복하며 배운 것

하나를 고치면 예전에 되던 것이 깨진다

규칙이 늘어날수록 생기는 일입니다. 해결책은 테스트입니다. 사례를 고칠 때마다 그 알림 문구를 '이 문구는 이렇게 읽혀야 한다'는 테스트 예시로 저장해 두면, 다음에 다른 것을 고칠 때 자동으로 전부 다시 검사합니다. 2장의 GitHub Actions가 빌드 전에 이 테스트를 돌리고, 하나라도 깨지면 설치 파일을 만들지 않습니다.

요청할 때 이렇게 덧붙이면 됩니다. "이 문구를 테스트에 추가하고, 예전 테스트도 다 통과하는지 확인해 줘."

AI가 "고쳤습니다"라고 했는데 폰에서는 그대로다
  • 빌드가 끝났는지 확인하세요. GitHub Actions에 초록 체크가 뜨기 전에 받으면 예전 버전입니다.
  • 받은 뒤 덮어 설치를 했는지, 브라우저가 예전 파일을 다시 열지 않았는지 확인하세요.
  • 예전에 온 알림은 다시 처리되지 않습니다. [놓친 결제 다시 읽기]를 누르거나 새 결제로 확인하세요.
  • 그래도 그대로면 '최근 감지 알림' 캡처를 다시 보내세요. 처리 결과 문구가 달라졌다면 진전이 있는 것입니다.
한 번에 여러 개를 말했더니 일부만 고쳐졌다

한 메시지에 한두 개씩 보내세요. 여러 개라면 번호를 붙여 "1번부터 하나씩 고치고 각각 결과 알려 줘"라고 하면 빠뜨리지 않습니다.

4장 체크리스트
  • 결제할 때마다 앱에 제대로 적혔는지 확인하는 습관을 들였다
  • 보고에 '무슨 일 / 기대와 실제 / 캡처'를 넣는다
  • 앱 안에 진단 화면(받은 원문 + 처리 결과)을 만들었다
  • 고친 사례는 테스트에 추가해 달라고 요청한다
  • 캡처 속 이름·카드번호는 가리고 보낸다
  • 빌드 완료(초록 체크) 후 덮어 설치해서 확인한다
