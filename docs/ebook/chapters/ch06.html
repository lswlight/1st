무엇을 했나내 폰의 기록을 아이폰 가족이 보게 하기

여기까지의 자동가계부는 내 폰 안에서만 동작했습니다. 기록이 폰 밖으로 나가지 않으니 안전하지만, 가족은 볼 수 없습니다. 저자의 아내는 아이폰을 쓰기 때문에 앱을 깔 수도 없습니다. 원한 것은 단순했습니다.

실제 요청
나
나는 남편의 기록을 와이프가 웹이나 어플에 들어가면 바로 볼 수 있는 형태를 원해

이를 위해 서버가 필요했습니다. 서버는 인터넷에 항상 켜져 있는 컴퓨터로, 내 폰이 기록을 올려 두면 가족이 언제든 꺼내 볼 수 있게 해 줍니다. 이 장에서는 처음에 쓴 구글 시트 방식이 왜 부족했는지, 그리고 무료 서버로 옮긴 과정을 따라갑니다.

왜구글 시트에서 전용 서버로 바꾼 이유

처음에는 AI가 가장 간단한 방법으로 구글 시트를 제안했습니다. 앱이 기록을 구글 시트에 올리고(Apps Script라는 구글의 작은 프로그램 사용), 가족은 그 시트를 보는 방식입니다. 만들어 써 보니 아쉬움이 컸습니다.

실제 대화 · 방향 바꾸기
나
결국 내보내기 같다. 남편 기록을 아내가 웹이나 앱에서 바로 보는 형태를 원한다. 다른 사람도 쓰게 할 거라 공유 서버 방식으로 바꿔야 한다.
나
플레이스토어에 올려 다른 사람들도 쓰게 할 계획이야. 공유 서버 방식으로 바꿔야 해.
구글 시트 방식전용 서버 방식
가족이 보는 화면표(스프레드시트) 그대로가계부 모양의 웹 화면
처음 설정사용자마다 시트·스크립트를 만들어야 함앱에서 버튼 한 번
다른 사람에게 배포사람마다 설정을 해 줘야 해서 어려움누구나 같은 서버를 씀
비용무료무료 한도 안(하루 10만 요청)

결정적인 이유는 "다른 사람도 쓰게 할 것"이었습니다. 나 혼자 쓰는 앱이라면 시트도 괜찮지만, 플레이스토어에 올릴 앱이라면 사용자가 아무 설정 없이 버튼만 누르면 되어야 합니다. 이처럼 앱의 목표가 바뀌면 구조도 바뀌어야 합니다. 목표가 바뀐 순간 AI에게 그 사실을 알려 주세요.

AI가 고른 서버는 Cloudflare의 무료 서비스 두 가지입니다.

보안을 위해 정한 것

  • 가족 방마다 열쇠 두 개: 기록을 올리는 쓰기 키(앱만 가짐)와 보기만 하는 보기 링크.
  • 쓰기 키는 서버에 원래 값이 아니라 해시(원래 값을 알아낼 수 없게 바꾼 지문)로만 저장.
  • 보기 링크는 https://graftkorea.com/v/… 뒤에 추측하기 어려운 무작위 값이 붙음.
  • 서버에는 이름(예: 남편)·사용처·금액·카드·시각만 보냄. 원본 알림 문구·전화번호·계좌번호는 보내지 않음.
  • [가족 공유 끄기]를 누르면 서버의 가족 방과 내역이 모두 지워지고, 보낸 링크도 더 이상 열리지 않음.
이 결정들이 나중에 그대로 쓰였다 플레이스토어의 '데이터 보안' 설문(10장)에서 "어떤 데이터를 보내나", "삭제할 수 있나", "전송 중 암호화하나"를 묻습니다. 처음부터 보내는 정보를 줄이고 삭제 기능을 만들어 둔 덕분에 설문에 그대로 답할 수 있었습니다.

따라 하기가족 공유를 쓰는 법 (사용자 입장)

  1. [가족] 탭 → [가족 공유 시작하기]내 이름(예: 남편)을 넣고 시작을 누르면 서버에 가족 방이 만들어집니다.
  2. 보기 링크를 카카오톡으로 보내기만들어진 링크를 가족에게 보냅니다.
  3. 가족은 링크를 열기만 하면 끝가입·설치가 필요 없습니다. 아이폰은 사파리에서 열고 공유 → 홈 화면에 추가하면 앱처럼 열립니다.
  4. 안드로이드 가족도 함께 기록하려면[공유 설정] → 초대 코드 보내기 → 가족 폰의 [가족] 탭 → 받은 링크·초대 코드로 참여하기.

가족이 보는 웹 화면

  • 이번 달 남은 돈과 수입·지출 합계
  • 사람별: 남편·아내처럼 누가 얼마나 썼는지
  • 카드별 실제 지출
  • 내역: 날짜별로 사용처·시각·사람·카드
  • [새로고침]을 누르면 최신 기록. 결제는 기록될 때마다 자동으로 올라가고, 실패하면 다음에 다시 보냅니다.

아이폰 가족은 앱을 깔 수 없지만, 이 화면을 홈 화면에 추가해 두면 앱처럼 씁니다. 저자의 아내도 이렇게 씁니다.

따라 하기서버를 직접 만들기 (처음 한 번, PC로 10분)

처음에는 저자가 Cloudflare 대시보드에서 직접 서버를 만들었습니다. AI가 단계별로 알려 주었고, 서버 코드(worker.js 파일 하나)는 AI가 만들어 저장소에 넣어 두었습니다. 화면 메뉴 이름은 Cloudflare가 자주 바꾸니, 다르면 AI에게 지금 보이는 화면을 캡처해 보내세요.

  1. Cloudflare 가입과 로그인dash.cloudflare.com. 2단계 인증을 켭니다.
  2. D1 데이터베이스 만들기Storage & Databases → D1 SQL Database → Create → 이름 moneybook → Create.
  3. Worker 만들기Compute(Workers) → Workers & Pages → Create → Worker → 'Hello World' 선택 → 이름 moneybook-sync → Deploy.
  4. 코드 붙여 넣기Edit code → 기본 코드를 모두 지우고 저장소의 sync-server/worker.js 내용을 통째로 붙여 넣기 → Deploy.
  5. D1 연결(바인딩)Worker 화면 → Settings → Bindings → Add → D1 database → 변수 이름 DB, 데이터베이스 moneybook 선택 → Deploy.
  6. 동작 확인https://moneybook-sync.<내계정>.workers.dev를 브라우저로 열어 "자동가계부 가족 공유 서버가 동작 중입니다."가 보이면 성공. 표는 첫 요청 때 자동으로 만들어집니다.
  7. 앱에 서버 주소 넣기AI에게 "서버 주소는 ○○야, 앱 기본값으로 넣어 줘"라고 하면 다음 빌드부터 반영됩니다.
바인딩 이름은 정확히 DB 서버 코드는 데이터베이스를 DB라는 이름으로 찾습니다. 변수 이름을 db나 moneybook으로 하면 서버가 데이터베이스를 못 찾습니다. 대소문자까지 똑같이 넣으세요.

바이브 코딩"니가 해줄 수 없나?": 배포를 AI에게 맡기기

서버 코드를 고칠 때마다 대시보드에 들어가 코드를 다시 붙여 넣는 일이 번거로웠습니다. 그래서 물었습니다.

대화 · 반복 작업 넘기기 (내 말은 원문, AI 답은 요약)
나
니가 해줄 수 없나?
AI
Cloudflare에서 API 토큰을 만들어 주시면 제가 직접 배포할 수 있습니다. 필요한 권한만 담은 토큰을 만들고, 채팅창이 아니라 보안 입력창으로 전달해 주세요. 작업이 끝나면 토큰을 지우면 됩니다.

API 토큰은 "이 프로그램에게 내 계정의 이 일만 허락한다"는 출입증입니다. 비밀번호와 달리 권한을 좁게 줄 수 있고, 언제든 지울 수 있습니다. 저자는 이 토큰을 회사 Cloudflare 계정으로 서버를 옮길 때 만들었고, 그 뒤로는 서버 코드 수정·배포·도메인 연결까지 AI가 했습니다. 토큰 만드는 화면은 7장에서 단계별로 보여 줍니다.

토큰은 채팅에 붙여 넣지 않는다 API 토큰은 비밀번호와 같습니다. 채팅창에 붙여 넣으면 대화 기록에 남습니다. Claude Code 클라우드 세션은 보안 입력창(환경의 비밀값 설정)을 띄워 주므로 거기에 넣으세요. 저장소 파일에도 절대 넣지 않습니다. 작업이 끝나면 Cloudflare에서 토큰을 삭제합니다.

막혔던 점서버를 만들며 겪은 것

대시보드 메뉴 이름이 안내와 다르다

클라우드 서비스의 화면은 자주 바뀝니다. 안내한 메뉴가 안 보이면 지금 화면을 캡처해 "이 화면에서 어디를 눌러?"라고 물어보세요. 메뉴 이름보다 화면 한 장이 빠릅니다.

서버 주소가 'workers.dev'라 길고 낯설다

가족에게 보내는 링크가 낯선 주소면 의심받기 쉽습니다. 나중에 회사 도메인 graftkorea.com을 사서 같은 서버에 연결했고(7장), 보기 링크도 https://graftkorea.com/v/…로 바뀌었습니다. 같은 서버가 회사 첫 화면(/), 앱 소개(/app), 개인정보처리방침(/privacy), 이용약관(/terms), 서버 확인(/health)까지 함께 맡습니다.

AI가 서버가 잘 도는지 어떻게 알지?

AI에게 "앱이 바뀔 때마다 서버도 실제로 동작하는지 자동으로 확인해 줘"라고 했습니다. 그래서 GitHub Actions가 빌드할 때마다 가족 방 만들기 → 기록 올리기 → 받기 → 삭제까지 실제로 해 보고 결과를 남깁니다. 사람은 초록 체크만 보면 됩니다.

6장 체크리스트
  • 앱의 목표(나만 쓰기 / 남도 쓰기)가 바뀌면 AI에게 알렸다
  • 서버로 보내는 정보를 최소로 정했다(원본 문구·계좌번호 제외)
  • 공유 끄기 = 서버 기록 삭제가 되도록 만들었다
  • Cloudflare에 D1 → Worker → 코드 → 바인딩(DB) 순서로 서버를 만들었다
  • 서버 주소를 브라우저로 열어 동작을 확인했다
  • AI에게 배포를 맡길 땐 권한을 좁힌 API 토큰을 보안 입력창으로 전달하고, 끝나면 삭제한다
