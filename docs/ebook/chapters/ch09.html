따라 하기① Android 16(API 36) 대상으로 올리기

구글은 매년 "새 앱은 최신 안드로이드 버전을 대상으로 만들어야 한다"는 기준을 올립니다. 2026년 8월 31일부터는 Android 16, 즉 API 36입니다. 'API 레벨'은 안드로이드 버전마다 붙은 번호라고 생각하면 됩니다.

요청 예시
나
플레이스토어에 올리려고 해. 지금 새 앱이 지켜야 하는 대상 API 기준에 맞춰 줘. 바뀌는 화면 문제가 있으면 같이 고치고, 최신 안드로이드 에뮬레이터에서 화면도 확인해 줘.

AI가 한 일은 다음과 같습니다. 이름은 몰라도 되지만, 이런 일이 필요하다는 것만 알아 두세요.

  • compileSdk·targetSdk를 36으로: 앱이 Android 16 기준으로 동작한다고 선언.
  • 빌드 도구(AGP) 업그레이드: 새 기준에 맞는 빌드 도구로 교체.
  • 화면 끝까지 그리기(edge-to-edge) 대응: 상단·하단이 시스템 바와 겹치지 않게 여백 처리(5장 그림).
  • Android 16 에뮬레이터에서 실제로 띄워 화면 확인: GitHub Actions에서 가상 폰을 켜고 설치·실행·캡처까지 자동으로.
기준 날짜는 해마다 바뀝니다 이 책을 읽는 시점에는 기준이 더 올라가 있을 수 있습니다. AI에게 "지금 기준이 뭔지 확인해 줘"라고 먼저 물어보세요. Play Console도 기준에 못 미치는 AAB는 업로드 단계에서 거부합니다.

따라 하기② 패키지 이름: 한 번 정하면 영원히

패키지 이름(applicationId)은 앱의 주민등록번호 같은 고유 ID입니다. 스토어 주소(play.google.com/store/apps/details?id=…)에도 들어가고, 첫 업로드 후에는 바꿀 수 없습니다. 보통 회사 도메인을 거꾸로 쓰고 앱 이름을 붙입니다.

패키지 이름용도
com.lswlight.moneybook지금까지 링크로 설치하던 앱(가족용). 그대로 유지
com.graftkorea.moneybook플레이스토어용 새 앱(회사 도메인 기반)

기존 앱의 이름을 바꾸면 이미 깔려 있는 가족 폰의 앱이 '다른 앱'이 되어 업데이트가 안 되고, 지우고 새로 깔면 기록이 사라집니다. 그래서 예전 앱은 예전 이름 그대로 두고, 스토어용은 새 이름으로 따로 빌드했습니다. 그 결과 저자 폰에는 두 앱이 따로 설치됩니다(테스트할 때 헷갈리지 않게 주의).

요청 예시
나
플레이스토어용은 com.graftkorea.moneybook으로 하고, 가족이 쓰는 기존 APK는 예전 이름 그대로 둬서 데이터가 유지되게 해 줘.

따라 하기③ 업로드 키와 AAB

AAB와 두 개의 키

플레이스토어에는 APK가 아니라 AAB(Android App Bundle, 스토어 업로드용 앱 파일)를 올립니다. 구글이 AAB를 받아 사용자 폰에 맞는 APK를 만들어 줍니다. 서명은 두 단계입니다.

이것을 Google Play 앱 서명이라고 합니다. 진짜 중요한 배포 키는 구글이 안전하게 보관하고, 나는 업로드 키만 관리합니다. 업로드 키를 잃어버려도 구글에 요청해 바꿀 수 있습니다.

업로드 키 만들기와 자동 빌드

  1. AI에게 업로드 키 생성과 AAB 자동 빌드 요청"플레이스토어용 업로드 키를 만들고, GitHub Actions에서 AAB를 자동으로 만들어 줘. 키와 비밀번호는 저장소에 넣지 말고 GitHub Secrets에서 읽게 해 줘."
  2. AI가 키 파일과 비밀번호를 만들어 안전하게 전달키 파일(키스토어)은 GitHub Secrets에 넣을 수 있게 글자(base64)로 바꾼 값으로 받습니다. 이 값들은 비밀번호 관리자 등 안전한 곳에 따로 보관하세요.
  3. GitHub Secrets에 4개 직접 입력(아래 따라 하기)
  4. 빌드 확인Secrets가 있으면 Actions가 AAB를 만들어 Artifacts(로그인한 저장소 관리자만 받을 수 있는 보관함)에 올립니다. 누구나 받는 Releases 링크에는 올리지 않습니다.
AI가 GitHub Secrets에 비밀값을 넣으려다 막혔다

AI는 보안 정책상 저장소의 비밀값 설정을 직접 바꿀 수 없었습니다. 이것은 고장이 아니라 올바른 안전장치입니다. 비밀값은 사람이 GitHub 설정 화면에서 직접 넣었습니다.

GitHub Secrets에 직접 넣기

  1. GitHub 저장소 → Settings(저장소 관리자만 보입니다)
  2. 왼쪽 메뉴 Secrets and variables → Actions
  3. New repository secret을 눌러 이름(Name)과 값(Secret)을 넣고 Add secret. 아래 4개를 반복합니다. 이름은 AI가 정한 것과 글자 하나까지 똑같이 넣어야 합니다.
이름(Name)값(Secret)
UPLOAD_KEYSTORE_BASE64업로드 키 파일을 글자로 바꾼 값
UPLOAD_KEYSTORE_PASSWORD키 파일 비밀번호
UPLOAD_KEY_ALIAS키 별칭(이름)
UPLOAD_KEY_PASSWORD키 비밀번호
절대 하지 말 것
  • 업로드 키 파일·비밀번호를 저장소에 커밋하기 (공개 저장소면 누구나 가져갑니다)
  • AAB를 공개 Releases 링크에 올리기
  • 비밀번호를 캡처해서 공유하기. Secrets는 한 번 넣으면 GitHub에서도 다시 볼 수 없으니, 원본은 안전한 곳에 따로 보관하세요.

따라 하기⑥ 스크린샷 5장

스토어 스크린샷은 사람들이 설치를 결정하는 가장 중요한 이미지입니다. 구글의 추천(프로모션) 조건은 한 변 1,080px 이상, 4장 이상입니다. 저자는 5장을 만들었습니다.

  1. 에뮬레이터에서 자동 캡처AI가 가상 폰의 화면 크기를 1080×1920으로 맞추고, 예시 데이터를 넣은 앱 화면을 자동으로 찍었습니다. 내 실제 결제 내역이 스토어에 나가지 않게 가짜 예시 데이터를 씁니다.
  2. 설명 문구 얹기각 화면 위에 "카드 알림이 오면 자동으로 기록" 같은 한 줄 문구를 크게 얹었습니다.
  3. 묶음으로 받기아이콘·그래픽·스크린샷을 store-assets.zip 하나로 받아 Play Console에 올렸습니다(10장).
요청 예시
나
플레이스토어 스크린샷 5장 만들어 줘. 1080×1920, 예시 데이터로 홈·달력·그래프·카드별·가족 화면. 위에 짧은 설명 문구 넣어서.

따라 하기⑦ AI 애셋 라벨

스토어 등록정보를 저장하면 AI 애셋 선언을 묻습니다. 아이콘·그래픽·문구를 AI로 만들었다면 사실대로 표시해야 합니다. 저자는 모두 AI로 만들었으므로 'AI를 사용하여 생성 또는 수정한 것으로 애셋 라벨 지정'을 고르고, 다음 단계에서 애셋마다 라벨을 붙였습니다.

9장 체크리스트
  • 지금 시점의 대상 API 기준(2026년: API 36)에 맞췄고 최신 에뮬레이터로 화면을 확인했다
  • 패키지 이름을 회사 도메인 기반으로 정했다(첫 업로드 후 변경 불가)
  • 업로드 키를 만들고 GitHub Secrets 4개를 직접 넣었다(원본은 안전한 곳에 보관)
  • Actions에서 AAB가 만들어져 Artifacts에 올라온 것을 확인했다
  • 무료/유료, 앱 이름, 카테고리를 정했다
  • 아이콘(512×512), 그래픽 이미지(1024×500), 스크린샷(1080×1920, 4장 이상)을 준비했다
  • AI로 만든 애셋에 라벨을 지정했다
