# 전자책 제작용 인수인계 자료: 직장인의 바이브 코딩 앱 제작 → 구글 플레이스토어 등록

이 문서는 실제로 진행한 프로젝트(안드로이드 '자동가계부' 앱)의 전 과정을 정리한 것이다.
이것을 바탕으로 **"직장인이 바이브 코딩(AI에게 말로 시켜 코드를 만드는 방식)으로 앱을 만들고 구글 플레이스토어에 등록하기"** 전자책(PDF)을 만든다.

- 저자(사용자): 타이어 코오드 접착액을 연구하는 직장인 연구원. 개발자가 아님. 갤럭시(안드로이드) 사용, 아내는 아이폰.
- 도구: Claude Code(클라우드 세션, 휴대폰·PC 앱에서 대화) + GitHub 저장소 `lswlight/1st` + GitHub Actions(자동 빌드) + Cloudflare(서버·도메인) + Google Play Console
- 사용자는 코드를 직접 쓰지 않았다. 원하는 기능을 말하고, 폰에서 써 보고, 문제를 캡처해 보내는 방식으로만 진행했다.
- 기간: 2026년 10월 말 ~ 11월 12일 (플레이스토어 심사 제출까지)

## 0. 전자책 작성 원칙

- 독자: 코딩을 모르는 직장인. 전문 용어는 처음 나올 때 쉬운 말로 풀어 쓴다 (예: APK = 앱 설치 파일, AAB = 플레이스토어 업로드용 앱 파일).
- 각 장은 "무엇을 했나 → 왜 그렇게 했나 → 화면 따라 하기(단계별) → 막혔던 점과 해결 → 체크리스트" 구조를 권장.
- AI에게 실제로 어떻게 요청했는지 **대화 예시(사용자가 실제로 한 말)** 를 넣으면 바이브 코딩 책으로서 가치가 크다. 아래 '사용자 발화 모음' 참고.
- 비밀값(업로드 키 비밀번호, API 토큰, 키스토어 파일), 개인 주소·전화번호, 이메일 중 개인 메일은 **절대 넣지 않는다.** 회사 연락처는 `graft.korea@gmail.com`, 회사 사이트는 `https://graftkorea.com` 만 사용.
- 이미지: 저장소의 이미지(`docs/ebook/images/`, `expense-app/docs/…`)와, 사용자가 새 세션에 직접 올려 주는 **`ebook-screenshots.zip`**(Play Console·Cloudflare·Search Console·GitHub·폰 화면 캡처 39장, 아래 본문의 `play-…`, `cf-…`, `sc-…`, `gh-…`, `domain-…`, `app-01-…` 파일)을 쓴다. 이 캡처들은 계정 화면이라 공개 저장소에 올리지 않았다. **저장소에 커밋하지 말고** PDF 안에만 넣는다. 이미지에 개인정보(주소·전화번호·개인 메일·계정 ID)가 보이면 흐리게 처리하거나 쓰지 않는다.
- zip 이 아직 없으면 사용자에게 올려 달라고 먼저 요청하고, 그동안 저장소 이미지만으로 작업한다.
- 한국어로 쓴다.

## 1. 전체 흐름 (전자책 목차 제안)

1. 시작하기: 바이브 코딩이란, 준비물(Claude Code, GitHub 계정), 비용
2. 첫 앱 만들기: "카드 알림을 읽어 자동으로 적는 가계부"를 말로 설명해 만들기
3. 폰에 설치하기: APK 받기, '출처를 알 수 없는 앱' 허용, 설치 가이드 이미지
4. 써 보며 고치기(반복 개선): 실제 알림으로 테스트 → 캡처 보내기 → 수정 → 재설치 (사례 모음)
5. 기능 키우기: 해외 결제·환율, 카드 혜택, 계좌이체 구분, 달력·그래프·카드별, 디자인 개편
6. 가족 공유와 서버: 구글 시트 방식 → 전용 서버(Cloudflare Workers + D1) 방식으로 바꾼 이유와 과정
7. 회사 준비: 사업자, DUNS 번호, 회사용 구글 계정, 회사 도메인(graftkorea.com), 회사 사이트·개인정보처리방침·이용약관
8. Google Play Console 조직 계정 만들기와 인증(신원, 웹사이트, 판매자 상태)
9. 출시 준비: Android 16 대응, 패키지 이름, 업로드 키와 AAB, 아이콘·그래픽·스크린샷
10. 내부 테스트 → 스토어 등록정보 → 앱 콘텐츠(등급·데이터 보안 등) → 프로덕션 → 심사 제출
11. 부록: 체크리스트, 비용 정리, 자주 막히는 지점 Q&A, 용어집

분량이 많으면 장별로 PDF를 나누고 마지막에 통합본을 만든다.

## 2. 단계별 상세 기록

### 2-1. 앱 아이디어와 첫 버전
- 사용자 첫 요청(원문): "나는 수입 지출 앱을 만들고 싶어. 다른 복잡한 기능은 빼고 나의 수입(월급)을 입력하고 내가 사용하는 카드실적 카카오톡 or 문자 or 카드지출 앱의 알림이 날라오면 이를 캐치하고 자동으로 바로 기입을 하는 형태의 어플을 만들고 싶어."
- 구현 방식: 안드로이드 '알림 접근(NotificationListenerService)'으로 문자·카카오톡·카드앱 알림을 읽고, 정규식으로 금액·가맹점·카드사를 뽑아 휴대폰 안 데이터베이스(SQLite)에 저장. 외부 라이브러리 없이 안드로이드 기본 기능만 사용.
- 빌드: 사용자의 PC에 개발 도구를 깔지 않고, GitHub Actions(클라우드)에서 자동으로 APK를 만들어 GitHub Releases의 고정 링크에 올림 → 폰에서 링크로 바로 받음.
  - 다운로드 링크: `https://github.com/lswlight/1st/releases/download/moneybook-latest/moneybook.apk`
- 같은 서명 키(디버그 키를 저장소에 보관)로 매번 빌드해 업데이트 설치 시 데이터가 유지되게 함.

### 2-2. 설치에서 막힌 점
- "앱이 설치되지 않았습니다" → 서명/빌드 설정 문제를 수정해 해결.
- 구글 플레이 프로텍트·갤럭시 '자동 차단' 경고 → 설치 가이드 이미지를 만들어 가족에게 공유.
  - 설치 가이드 이미지: `expense-app/docs/install-guide-1.png`, `install-guide-2-1.png`, `install-guide-2-2.png`, `install-guide-3.png` (실제 화면 캡처에 빨간 박스·번호로 주석)
  - 교훈: 사용자는 "보낸 사진 그대로 쓰지 말고, 사진 위에 안내를 그려 달라"고 요청함 → 실제 캡처 + 주석 방식이 이해가 쉽다.

### 2-3. 써 보며 고치기 (반복 개선 사례 – 전자책 핵심 사례)
각 사례는 "폰에서 실제 알림 → 기록이 안 됨/잘못됨 → 캡처 전송 → 원인 → 수정" 순서.
- 카카오톡 알림톡이 안 잡힘 → 카카오톡 앱 알림도 읽도록 대상 추가. 같은 문구로 테스트하면 '중복'으로 걸러지는 것도 확인.
- 하나카드 해외(엔화) 결제 미기록 → 외화 금액 인식 + 환율 연동(무료 환율 API, 하루 1회) + 해외 수수료(기본 2%) 반영.
  - 안드로이드 기기에서만 나는 정규식 오류(`}` 처리)로 해외 결제에서 앱 처리 실패 → 기기에서 도는 테스트를 추가해 재발 방지.
- 카드 혜택(커피 할인 캐시백, 마이너스 금액)이 지출로 기록 → '카드 혜택: …' 수입으로 처리.
- MG새마을금고 체크카드 출금 알림 미기록 → 은행 앱 출금 알림 인식.
- 체크카드 결제 vs 계좌이체 구분 요청: 사용자가 "결제 알림에는 '승인' 알림이 따로 온다, 이걸 기준으로 구분할 수 있지 않을까?"라고 아이디어 제시 → 승인/결제/카드 단어가 있으면 결제, 은행 출금만 있으면 제외. 같은 금액 입금이 5분 안에 오면 내 계좌 간 이체로 보고 삭제.
- KB국민카드 RCS 알림에서 가맹점이 '시각'으로 기록 → 가맹점 추출 규칙 보완('미소가득주유소').
- 토스 '적립' 알림이 지출로 기록 → 적립 알림 제외.
- 해외 달러 결제 형식 다양화(“33.83(USD)”, “31.85 달러”) 대응.
- 네이버페이 결제 알림 대응(네이버 앱).
- 토스 결제가 실제로는 체크카드 결제 → 토스포인트·토스머니 결제는 결제수단으로 기록, 카드사 알림이 뒤따라오면 카드 이름을 실제 카드로 바꿈.
- 현대카드 '11/12 결제금액 … (11/01기준)' 청구 안내가 지출로 기록 → 청구 안내 문구 제외. (이미지: `docs/ebook/images/app-01-bill-notice-misrecorded.jpg`)
- '최근 감지 알림' 화면을 만들어, 기록이 안 될 때 앱이 알림을 받았는지/못 읽었는지 사용자가 직접 확인하고 캡처해 보낼 수 있게 함. 이것이 원격으로 고치는 데 큰 도움이 됨.

### 2-4. 화면·디자인
- 달력(날짜별 지출 색), 그래프(일별·월별), 카드별 실제 지출(결제 − 취소 − 혜택) 화면 추가.
- 사용자 피드백: 글자 겹침, 상단이 답답함, 뒤로가기 버튼 필요 → 수정.
- 디자인 개편 2.0 '파스텔 라이프': 크림색 바탕, 초록 포인트, 아래쪽 탭(홈·달력·카드·가족·설정). 3가지 시안 중 사용자가 C 선택.
- 앱 화면 이미지: `expense-app/docs/screens/screen1-main-v2.png` ~ `screen5-family-v3.png`, `screen6-family-web.png`
- Android 15/16의 '화면 끝까지 그리기(edge-to-edge)' 때문에 상단이 겹치는 문제 → 시스템 바 여백 처리. (이미지: `docs/ebook/images/app-02-android16-edge-to-edge.png`)

### 2-5. 시도했다가 접은 기능 (전자책에 '판단 사례'로 유용)
- 카드 혜택·전월 실적 자동 계산: 마이데이터 표준 API에 카드 실적이 빠져 있고(2022년 기준 기사), 카드사 공개 API도 없음 → 사용자가 "안 하는 게 낫겠다"고 결정. 바이브 코딩에서도 '안 할 결정'이 중요하다는 사례.

### 2-6. 가족 공유: 구글 시트 → 전용 서버
- 처음엔 구글 시트(Apps Script)에 올려 공유 → 사용자: "결국 내보내기 같다. 남편 기록을 아내가 웹이나 앱에서 바로 보는 형태를 원한다. 다른 사람도 쓰게 할 거라 공유 서버 방식으로 바꿔야 한다."
- 바꾼 구조: Cloudflare Workers(서버 프로그램, 무료 한도 넉넉) + D1(데이터베이스).
  - [가족 공유 시작하기] 한 번 → 가족 방 생성 → 보기 링크(`https://graftkorea.com/v/…`)를 카톡으로 전달 → 아이폰·PC는 웹으로 바로 봄.
  - 안드로이드 가족은 초대 코드로 함께 기록. 공유 끄기 = 서버 내역 삭제.
  - 쓰기 키는 서버에 해시로만 저장, 보기 링크는 추측 어려운 무작위 값.
- 처음엔 사용자가 Cloudflare 대시보드에서 직접 서버 만들기(D1 생성 → Worker 생성 → 코드 붙여넣기 → 'DB' 바인딩) → 나중엔 회사 계정으로 옮기며 **API 토큰을 만들어 AI가 직접 배포**.
- 서버 코드: `sync-server/worker.js` (회사 첫 화면 `/`, 앱 소개 `/app`, 개인정보처리방침 `/privacy`, 이용약관 `/terms`, 가족 공유 API, 서버 확인 `/health`)
- 웹 보기 화면 이미지: `expense-app/docs/screens/screen6-family-web.png`

### 2-7. 회사·계정·도메인 준비
- 플레이스토어 조직(회사) 계정: 개인 계정은 '테스터 12명 × 14일 비공개 테스트' 조건이 있지만 조직 계정은 없음 → 조직 계정 선택.
- 필요: 사업자 + **D-U-N-S 번호**(무료 발급, 수일~수주).
- 회사 이름은 GRAFT. 노션의 앱 소개 페이지(사업자 정보)는 DUNS 신청용으로만 사용하고 외부 공유는 안 함(상세 주소 노출 때문).
- 회사용 구글 계정을 새로 만듦(개인 계정과 분리, 2단계 인증 필수).
  - Play Console 질문 "지난 6개월간 다른 계정으로 Play Console에 접속했나요?" → 개인 계정으로 가입 페이지를 열어 본 적이 있어 '예'로 사실대로 답함.
  - "12개월간 게시할 앱 수" → 참고용 질문, 2개라고 답함.
- 회사 도메인: `graft.com` 은 이미 주인이 있음(이미지 `domain-01-taken.jpg`) → **Cloudflare에서 `graftkorea.com` 구입(.com, 연 11.17달러)**.
  - .com/.io/.ai 가격 차이: 도메인마다 관리 기관과 도매가가 다름(.com이 가장 싸고 안정, .ai는 수요 폭증·국가 도메인).
  - 등록자 정보: 회사 이름 GRAFT, DUNS와 같은 회사 주소(외부엔 자동 비공개). 이미지 `cf-01-domain-registrant-form.png`, `cf-02-domain-ready.png`
  - 새 도메인이 폰에서 바로 안 열림(“서버 IP 주소를 찾을 수 없음”, 이미지 `domain-02-dns-not-ready.jpg`) → 통신사 DNS 반영 지연. 비행기 모드 껐다 켜기, 와이파이 전환, 개인 DNS 설정, 기다리기로 해결.
- 회사 Cloudflare 계정을 새로 만들고(2단계 인증) 서버를 옮김. AI가 작업할 수 있게 **API 토큰** 생성(권한: 계정 D1 편집·Workers 스크립트 편집·계정 설정 읽기, 영역 Zone 읽기·DNS 편집·Workers 경로 편집). 토큰은 채팅에 붙여넣지 않고 보안 입력창으로 전달, 작업 후 삭제.
  - 이미지: `cf-03-token-templates.png` ~ `cf-07-token-summary.png`
- 회사 사이트 첫 화면: `docs/ebook/images/web-01-company-home.png`
- Search Console 도메인 인증: Cloudflare 자동 연결(Authorize) → 401 오류 화면이 떴지만 실제로는 TXT 기록이 들어가 인증 성공. 이미지 `sc-01-dns-authorize.png`, `sc-02-401-error.png`, `sc-03-verified.png`

### 2-8. Play Console 계정 설정

## 4. 자주 막힌 지점 Q&A (부록용)
- 알림이 기록 안 될 때: '최근 감지 알림'에서 받았는지 확인 → 캡처를 AI에게 보내기
- 새 도메인이 폰에서 안 열림: DNS 반영 대기, 비행기 모드, 개인 DNS
- 401 오류인데 인증은 됨: 실제 DNS 기록 확인
- 테스터 '항목을 찾을 수 없음': 참여 링크 → 계정 확인 → 대기
- 가독화 파일 경고: 난독화 안 했으면 무시
- 비밀값 저장: 사용자가 직접 GitHub Secrets에 입력, 채팅에 붙여넣지 않기
- AI가 영어로 답하면 "한국어로" 요청
