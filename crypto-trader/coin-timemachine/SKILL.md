# coin-timemachine

계획과 돈 사이에서 한 가지를 묻는다: 오늘이 이 종목의 최근 60일처럼 흘러간다면
이 계획은 얼마나 자주 목표에 먼저 닿고, 얼마나 자주 손절에 먼저 닿는가.
예측이 아니라 그 종목 자신의 최근 봉으로 만든 시뮬레이션이다.

```bash
python3 "<이 폴더>/tm.py" run                      # crt/plan.json, 10,000회, 시드 19
python3 "<이 폴더>/tm.py" run --write              # crt/timemachine.json 저장
python3 "<이 폴더>/tm.py" run --replays 20000 --seed 7
python3 "<이 폴더>/tm.py" run --symbol BTCUSDT --date 2026-10-28 --entry 80918 --stop 80824.89 \
    --target 81011.11 --entry-time 10:40 --stop-rule or-mid
```

## 방식

1. **재료:** 계획 날짜 이전의 전체 세션만 쓴다 (09:00 KST 시작, 5분봉 288개가 빠짐없이 있는 날).
   각 봉을 직전 봉 종가 대비 비율(시가, 고가, 저가, 종가)로 바꾼다.
2. **한 번 재현:** 진입가에서 시작해, 남은 봉마다 같은 시간대(앞뒤 2봉)의 과거 봉 하나를
   무작위로 골라 현재 가격에 맞춰 붙인다. 봉마다 손절을 먼저, 그다음 목표를 본다.
   한 봉이 둘 다 건드리면 손절로 센다. 시가가 손절 아래로 갭이면 손절이다 (-1R로 계산하지만 실제 체결은 더 나쁠 수 있다).
3. **10,000번** 반복해 익절 먼저, 손절 먼저, 둘 다 아님(청산 시한까지 보유), 플러스(익절 또는 시한에 진입가 위) 확률을 낸다.
4. **과거 기록:** 같은 규칙(같은 셋업, 같은 손절 규칙, 같은 R)을 과거 세션마다 실제로 적용한 결과. 가격 레벨 셋업은 생략한다.
5. **판정:** 한쪽에 닿은 경우 중 익절 비율을 본전 기준 1/(1+R)과 비교한다 (1R 50%, 2R 33%).
   5%p 미만이면 "동전 던지기에 가까움"(1R) 또는 "본전 근처", 5~15%p는 "약간 기욺", 15%p 이상은 "강하게 기욺".

청산 시한: 진입 후 6시간 (그날 09:00 세션 안에서). `--until HH:MM` 으로 바꾼다.
시드는 기본 19. 같은 계획, 같은 데이터, 같은 시드면 어디서나 같은 숫자가 나온다.

## 순서

1. `crt/plan.json` 이 오늘 계획인지 확인한다. 없으면 `/coin-plan` 으로 먼저 만든다.
2. `tm.py run --write`.
3. 이 순서로 말한다: 네 가지 확률, 청산 시점 가격 중앙값과 90% 범위, 평균 R, 과거 기록, 판정 줄과 그 아래 줄 (출력 그대로). 시드를 말한다.
4. 동전 던지기·본전 근처면 그대로 말한다. 꾸미지 않는다. 시뮬레이션과 과거 기록이 엇갈리면 그것도 말한다.
5. 평균 R은 수수료 전이다. 바이낸스는 왕복 0.20%, 업비트는 0.10%가 빠진다는 점을 덧붙인다.
6. 최근 60일 데이터이고 예측이 아니라고 한 번 말한다. 뉴스·상장·해킹·거시 이벤트는 그 60일에 없던 움직임을 만든다. `/coin-news` 로 확인을 권한다.
7. 그래도 진행하면 `/coin-plan` 의 `size` 로 넘긴다.

## 하지 않는 것

주문·수량 계산을 하지 않고, 계획을 바꾸지 않는다. 결과를 확실하다고 말하지 않는다.
수익 금액을 말하지 않는다. 진행 중인 봉이나 오늘 봉을 재료에 섞지 않는다. 투자 조언이 아니다.
